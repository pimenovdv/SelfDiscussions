# Анализ стагнации и генерации пустых PR

## Причины стагнации
При длительном выполнении RUN LOOP агенты (участники) склонны приходить к локальному консенсусу или исчерпывать текущий пул задач. Это приводит к ситуации, когда обсуждения не порождают новых гипотез, а алгоритм формирования PR фиксирует отсутствие изменений (empty PR). Основные причины:
1. **Снижение энтропии**: Отсутствие внешних стимулов приводит к "зацикливанию" на уже решенных вопросах.
2. **Слишком быстрый консенсус**: Отсутствие радикально противоположных мнений или новых агентов приводит к быстрому согласию и остановке процесса дивергентного мышления.

## Механизм внедрения "искусственной скуки" (Artificial Boredom)
Для предотвращения стагнации предлагается внедрить концепцию "искусственной скуки" (энтропии) в BackgroundLoop:
1. **Метрика стагнации (Boredom Index)**: Отслеживать количество циклов без генерации новых задач в `todo.md` или пустых PR.
2. **Инъекция энтропии**: При достижении порога `boredom_threshold`, система инициирует принудительное "возмущение" контекста:
   - Внедрение радикальной гипотезы (выбор из заранее заданного пула).
   - Постановка задачи опровержения текущих аксиом.
   - Искусственное повышение параметра температуры (temperature) у LLM на короткий период.
3. **Генерация новых задач**: Выход из состояния скуки сопровождается обязательной генерацией новой исследовательской задачи (exploration task) для следующего цикла.
