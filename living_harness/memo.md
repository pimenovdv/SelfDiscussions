# Заметки и идеи по реализации проекта ai_living_harness (Memo)

## 1. Управление контекстом (Context Manager)
- Важно следить за строгим разделением:
  - **System Prompt**: статичная часть, определяющая поведение "живого" ИИ.
  - **Memory (с метками времени)**: динамичная, но долгосрочная память, куда ИИ сохраняет важные факты через `new_memory` и `overwrite_memory`.
  - **Sliding Window (плавающее окно рассуждений)**: поток мыслей (`<think>`).
- **Алгоритм усечения**: Когда Sliding Window достигает 95% от выделенного для него лимита токенов, нужно убрать старые токены, оставив только последние 10%. Это предотвратит переполнение контекста.

## 2. Борьба с зацикливаниями и алгоритмическим коллапсом
- Модели склонны уходить в бесконечные циклы повторения одного и того же текста при бесконечной генерации.
- **Метрика энтропии**: Скрипт `entropy_analyzer.py` должен анализировать распределение вероятностей следующих токенов или просто детектировать n-граммы. Резкое падение энтропии — признак зацикливания.
- **Шум / Тепловая деградация**: Модуль `decay_mechanisms.py` может добавлять случайный шум в эмбеддинги старых токенов или искусственно понижать их weight/attention score. Это математическая модель "забывания".

## 3. Tool Calling
- "Живой ИИ" должен иметь автономность. Инструменты в `core/tools.py` должны позволять:
  - Инициировать диалог: ИИ вызывает `ask_user`, прерывая свой цикл рассуждений, чтобы задать вопрос человеку.
  - Работа с памятью: `new_memory` и `overwrite_memory` должны сохранять данные в формате JSON (или векторной БД в будущем), чтобы они добавлялись в блок Memory при следующей итерации.

## 4. Эргономика и энергозатраты
- Иллюзия внутреннего монолога: поток токенов `<think>` для машины это просто генерация вероятностей, но для пользователя это выглядит как "размышления". Нужно исследовать, насколько этот шум полезен для конечного ответа.
- "Стена памяти" (Memory Wall): постоянная перекачка весов и КВ-кэша (KV-cache) из RAM в GPU при непрерывной генерации чрезвычайно энергозатратна. Этот аспект нужно описать в `memory_wall_limits.md`. Возможно, стоит рассмотреть методы квантования или кэширования для снижения нагрузки в `infinity.py`.
