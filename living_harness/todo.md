# Общая цель
Реализовать "живой ИИ", который сможет рассуждать между запросами, спрашивать пользователя и иметь прочие реализации описанные в обсуждении. Это включает непрерывное рассуждение, управление памятью и удержание "живого" состояния.

# Промежуточные цели
Написание статей и как можно более широкое изучение гипотезы и идеи (от эргономики интерфейса до аппаратных барьеров).

# Структура будущего проекта
```
living_harness/
├── core/                  # Основная логика удержания модели в "живом" состоянии (harness)
├── memory/                # Управление контекстным окном (системный промпт, память, скользящее окно)
├── analytics/             # Скрипты для анализа сгенерированных токенов, энтропии и зацикливаний
├── experiments/           # Запуски малых моделей с разными параметрами
├── articles/              # Черновики и готовые научные статьи по результатам экспериментов
├── data/                  # Сохранение результатов (json, логи)
├── main.py                # Точка входа для запуска сеанса с моделью
├── infinity.py            # Простейший эксперимент-прототип
├── models.md              # Список моделей для экспериментов

└── todo.md                # Этот план развития проекта
```

# План развития и исследований
1. **Разделение контекста на системный промпт, память и окно рассуждений**
   - Контекст должен состоять из трех блоков: система, память (с метками времени), и плавающее окно. При заполнении плавающего окна до 95% происходит усечение ранних рассуждений до 10% лимита.
   - *Улучшение проекта:* Добавление модуля `memory/context_manager.py` для управления этими тремя зонами.

2. **Анализ энтропии распределения внимания и зацикливания**
   - На основе обсуждений об алгоритмическом срыве и коллапсе внимания, необходимо измерить деградацию энтропии в сгенерированных цепочках.
   - *Написание скрипта для анализа:* Создание `analytics/entropy_analyzer.py` для выявления циклов в результатах.

3. **Реализация функций `ask_user`, `new_memory`, `overwrite_memory`**
   - Внедрение tool calling: модель должна уметь инициировать диалог или обновлять записи в своем "буфере" (с учетом времени).
   - *Улучшение проекта:* Реализация базовых инструментов в `core/tools.py`.

4. **Тестирование ультракомпактной модели с размышлениями**
   - Запуск "бесконечного" потока на модели класса 0.5B (например, `Qwen2.5-0.5B` или `SmolLM2-360M`) для оценки того, как долго она может удерживать осмысленный `<think>` процесс без ухода в повторы.
   - *Добавление эксперимента / запуск эксперимента на небольшой модельке:* Создание и запуск `experiments/compact_think_loop.py`.

5. **Реализация "Морфологического некро-вычисления" (Архитектуры увядания)**
   - Введение математического штрафа (или шума) за доступ к старым данным, имитируя тепловую деградацию, как предложено в дискуссии, чтобы избежать коллапса внимания и стимулировать обновление.
   - *Улучшение проекта:* Добавление логики затухания релевантности в `core/decay_mechanisms.py`.

6. **Анализ иллюзии внутреннего монолога (Эргономика интерфейса)**
   - Оценка того, как "шум" из непрерывной генерации воспринимается человеком-наблюдателем и как это влияет на пользовательский опыт, следуя антропоцентричной критике Станислава.
   - *Написание научной статьи:* Черновик статьи `articles/illusion_of_monologue.md`.

7. **Анализ энергозатрат непрерывного вычисления (Проблема Стены Памяти)**
   - Теоретическая оценка вычислительных затрат на поддержание постоянного цикла генерации в архитектуре фон Неймана, основываясь на аргументах Илона и Макса.
   - *Написание научной статьи:* Черновик статьи `articles/memory_wall_limits.md`.
