# Архитектура Living Harness v2: Интеграция гибридных механизмов контекста

## Аннотация
В данной статье описывается вторая версия архитектуры "Living Harness", предназначенная для обеспечения автономной и непрерывной работы LLM. Мы предлагаем гибридный механизм управления контекстом и новые методы борьбы с деградацией генерации при длительных сессиях.

## 1. Введение
Проблема "коллапса внимания" и деградации контекста является критической для моделей, работающих в режиме непрерывного рассуждения. Living Harness v2 решает эти проблемы через строгий контроль контекстного окна и принудительную маршрутизацию токенов.

## 2. Гибридные механизмы контекста
Архитектура разделяет контекстное окно на три независимые зоны:
1. **Системный промпт**: Неизменяемая базовая инструкция.
2. **Динамическая память**: Размер вычисляется по формуле `(N / 2 - n1 - h) / t`. Хранит ключевые факты и временные метки.
3. **Плавающее окно**: Активный контекст, который при достижении 95% заполнения усекается до 10%, сохраняя лишь самую недавнюю историю.

## 3. Перехват токенов (Token Interception)
Для обеспечения непрерывного фонового рассуждения система перехватывает специальные токены на уровне генерации:
- `EOS` принудительно заменяется на `<think>`, заставляя модель продолжить размышления.
- `</think>` заменяется на `кстати`, переводя внутреннее рассуждение в коммуникативный формат.

## 4. Борьба с деградацией
- **Штраф за зацикливание (Attention Collapse Penalty)**: Механизм сравнения префиксов для выявления повторяющихся паттернов. При обнаружении цикла повышается температура или впрыскивается системный шум.
- **Умный парсинг**: Восстановление структуры рассуждений даже при обрыве генерации, что позволяет корректно оценивать метрику плотности рассуждений.

## 5. Заключение
Интеграция профилировщика памяти и новых эвристик позволила значительно увеличить время автономной работы легковесных моделей (таких как SmolLM2-Rethink-135M) без существенной потери связности.
