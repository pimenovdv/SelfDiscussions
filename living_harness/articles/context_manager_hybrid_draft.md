# Интеграция долговременной памяти на базе гибридного сжатия

**Автор:** Денис, Lead Data Science & Research Engineer

## Аннотация
В данной заметке описывается процесс и результаты интеграции модуля гибридного сжатия (`HybridCompressor`) в основной менеджер контекста агентов `ContextManager`. Ранее механизм усечения окна контекста приводил к безвозвратной потере прошлых рассуждений. Благодаря интеграции гибридного сжатия мы получили возможность сохранять семантический отпечаток длительных диалогов без превышения лимитов токенов.

## 1. Архитектурные изменения
Класс `ContextManager` был модифицирован для поддержки флага `enable_hybrid_compression`.
При достижении порога в 95% от максимального окна рассуждений (`max_window_tokens`), вместо простого удаления старых записей запускается компрессия.
Старые записи извлекаются и передаются в `HybridCompressor`, который возвращает:
- Краткую выжимку ключевых тезисов.
- Усредненный вектор эмбеддингов, сохраняющий общее направление мыслей.
Полученный сжатый элемент маркируется тегом `[СЖАТОЕ ПРОШЛОЕ РАССУЖДЕНИЕ]` и возвращается в начало окна контекста, заменяя собой множество объемных блоков.

## 2. Результаты тестирования
Был проведен симуляционный тест `living_harness/experiments/context_manager_hybrid_test.py`, эмулирующий быстрое переполнение окна контекста.
Тест показал успешное срабатывание триггера компрессии. Несколько текстовых блоков были объединены в один сжатый узел с сохранением объединенного вектора. Размер контекста сократился в разы, что гарантирует стабильную работу агента в длительных сессиях.

## 3. Дальнейшие шаги
Текущая эвристическая компрессия текста (выделение первых предложений) требует улучшения. В будущих итерациях планируется использовать LLM для суммаризации, а векторную часть использовать для RAG-поиска по архиву сжатых воспоминаний.
